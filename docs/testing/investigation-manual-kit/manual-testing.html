Test reproducible investigation snapshots

Follow the checks below in the current branch's MicrobeTrace build. Allow about 45–60 minutes for the core checks, plus time for the optional analysis and interruption checks. All cases, sequences, dates, locations, and relationships in this kit are fictional.

1. Get ready

  1. Save any investigation you want to keep. Open the build containing this feature. If running locally, start npm.cmd start from the project folder, then open http://localhost:4200. Accept the EULA and close the welcome panel.
  2. Use File → Add Data to reach the file-loading area. Choose the specified .microbetrace file, or drop it onto the file-loading area. Wait for the restored dashboard to appear. A saved session replaces the open investigation; it does not need a separate launch step.
  3. Begin each independent check with the file named in that check. This prevents a preceding calculation, disabled layer, or edited cohort from changing the expected counts.
  4. Open File → Investigation Workspace. Save investigation saves all data, settings, notes, cohorts, layers, and completed results together; no feature selections are needed. For the editing and analysis checks below, expand Optional tools, then open the relevant section: Edit cohorts, Edit relationship layers, Edit notes, or Run or change calculations. Close the workspace with its upper-right close button when you need to work in a dashboard pane. Allow about two seconds for input previews to refresh after edits.

3. Core acceptance checks

□ M01 Load the combined investigation

  1. Load 02-configured.microbetrace.
  2. Check the side-by-side 2D Network and Table panes. Only A/B/C should be visible. A/B are selected; D remains selected in the underlying data while hidden.
  3. Open File → Investigation Workspace. Find Left review and Right review, each showing three members, both checked. Find three enabled relationship layers, four notes, and Network statistics set to Cohort with a saved completed result.
  4. Note the saved result's completion time. Wait several seconds and revisit the panel.

Expected: no calculation starts automatically; the saved completion time remains unchanged. The retained note for deleted-review-cohort says Unresolved target. The cohort statistics preview is 4 eligible nodes · 2 edges.

□ M02 Create overlapping cohorts and keep hidden members

  1. Load 01-start.microbetrace. A/B/D are already selected. In Investigation Workspace, enter Left review and click Create from selection.
  2. Close the panel. In the Table's Nodes dataset, hold Ctrl (Command on macOS) and click A to deselect it, then E to select it. Verify that the selected rows are B/D/E.
  3. Reopen Investigation Workspace from File, create Right review, and check both cohort checkboxes. Set Network statistics to Cohort.
  4. Close the panel. Open top-toolbar Settings → Filtering. Under Subset Nodes, choose Region, equals, North. Click Apply Subset, then Done.
  5. Reopen Investigation Workspace from File. Click Left review's Select members. Clear the subset using the banner's Clear button, then inspect the Nodes table.

Expected: each cohort stays at three members despite filtering. Both checked cohorts resolve to four unique nodes A/B/D/E. Select members selects exactly A/B/D; it does not change which cohort checkboxes are checked.

□ M03 Rename, explicitly replace, and delete a cohort

  1. Load 02-configured.microbetrace. Rename Left review to Primary review, then click outside the name field.
  2. Clear the shared subset. Click Primary review's Select members. In the Table, Ctrl/Command-click B to deselect it. A/D should remain selected.
  3. Click Primary review's Replace from selection. Leave both cohorts checked.
  4. Delete Right review.

Expected: renaming keeps its ID and membership. Replacement changes Primary review to A/D (two members). The union before deletion is still A/B/D/E. After deleting Right review, Cohort scope resolves only A/D. Ordinary selection changes alone never replace saved cohort membership.

□ M04 Threshold, layer eligibility, and mixed-source edges

  1. Load 01-start.microbetrace. In Investigation Workspace, set Network statistics to Full. Check the preview: 6 nodes · 7 edges.
  2. Disable Genetic Distance. Check 6 nodes · 4 edges: BC/CD/EF/AF. Re-enable it.
  3. Disable Field contacts. Check 6 nodes · 5 edges: AB/AC/BC/DE/AF. BC survives through genetics; CD disappears. Re-enable it.
  4. Disable Imported relationships. Check 6 nodes · 6 edges. Re-enable it.
  5. Close the panel. In Settings → Filtering, set Filtering Threshold to 1, then Done. Reopen Investigation Workspace from File: expect 6 nodes · 6 edges. Repeat with 0: expect 6 nodes · 4 edges. Restore 3: expect 6 nodes · 7 edges.
  6. Switch to Table's Links dataset or inspect link details to verify that BC/CD retain both source contributions. Use a saved snapshot's _originAll field if the current table column shows only contributing visible sources.

Expected: source controls update shared visibility without deleting stored edges or source memberships. Mixed edges are counted once. Contact-only and imported-only edges are not removed by the genetic threshold.

□ M05 Layer names, order, color, and opacity

  1. Load 01-start.microbetrace. In Investigation Workspace, rename Field contacts to Interview evidence.
  2. Set its color to a clearly different color and opacity to about 0.5. Move it above Genetic Distance with the up arrow.
  3. Close the panel and inspect the 2D links. Check a contact-only edge (EF) and a mixed edge (BC/CD). Open View → Map and enable links in that pane's settings if necessary.
  4. Use Reset style, verify that normal link styling returns, then reapply an override for the save test.

Expected: explicit overrides take precedence over existing view colors; order determines precedence when more than one contributing layer has an override. Renaming changes the display name while the Source identity stays unchanged. Restoring a save preserves the final name, order, enabled states, and style values.

□ M06 Plain-text annotations and unresolved targets

  1. Load 02-configured.microbetrace. Under Annotations, leave Target as Investigation, enter Methods note <check sources>, and click Save note.
  2. Add a Node note targeting A, an Edge note targeting C-D, and a Cohort note targeting cohort-left (the ID is printed beneath Left review).
  3. Edit one note and click outside its text box. Observe the updated timestamp.
  4. Delete Left review. Inspect its cohort note. Delete another note using Delete note.

Expected: the deleted cohort's note remains and says Unresolved target. The explicitly deleted note disappears. Angle brackets remain literal text in the panel and downloaded HTML record. A note aimed at an ID that never existed is rejected when creating it.

□ M07 Compare all three scopes with known statistics

  1. Load 02-configured.microbetrace. Open View → Network Statistics.
  2. In Investigation Workspace's Network statistics row, choose Full, check the preview, and click that row's Run. Inspect the statistics Summary: 6 nodes, 7 links, 1 component.
  3. Choose Visible and Run: 3 nodes, 3 links, 1 component.
  4. Choose Cohort and Run: 4 nodes, 2 links, 2 components. Check Clusters for the exact AB and DE components.
  5. Uncheck both cohorts. Leave scope set to Cohort and try Run.

Expected: results follow the table in section 2. Cohort union deduplicates B/D and includes hidden D/E. Empty cohort scope produces an explanation and preserves the last completed result; it never substitutes the full graph.

□ M08 Save and reopen the complete analytical state

  1. Reload 02-configured.microbetrace. Set threshold 1, leave the North subset active, retain both cohort checkboxes, and add a distinctive note.
  2. In the 2D pane's Settings → Grouping → Controls, show Groups and set Group By to Ward. Enable group labels under Labels. Change a node color or label setting as well.
  3. Close settings. Drag a node to a distinctive position while pinned. Pan/zoom the network. Drag a dashboard divider and move a tab to another stack if desired. Keep Table and 2D Network open; optionally add Map and Network Statistics.
  4. Use Table's node-column picker to show Region/Ward. Apply a table-only column filter and note it separately from the shared North subset. Check that ordinary node selection is as intended.
  5. Run Network statistics in Cohort scope. Record its saved completion time. Immediately after a final pan/zoom, use File → Save, enter manual-roundtrip, choose session, uncheck Compress?, and Save.
  6. Change the threshold, grouping, cohort selection, note, layout, and camera. Then load the downloaded manual-roundtrip.microbetrace.
  7. Inspect Investigation, global settings, each open pane, Table filters/columns, selection, pin state, node position, dashboard split, and zoom/pan. Open the saved file in a text editor if checking exact memberships, IDs, or camera values.

Expected: all eight categories, selections, styling, and supported view settings return. Positions/camera/dashboard match within normal pixel and window-size differences. The calculation's completion time, run ID, recorded input IDs, and output are unchanged; reopening does not launch a replacement calculation.

  4. Click Run for Cohort statistics. The new input population is still four nodes, but now has zero eligible edges. Inspect the replacement time and four singleton components.

4. Analysis and interruption checks

Reload the indicated starting session before each operation/scope combination. Some operations modify links, alignment, or the base tree. Their later previews may correctly differ from the original fixture.

□ M14 Scope preview and successful calculation coverage

  1. Load 02-configured.microbetrace. For each operation below, set its scope to Full, Visible, and Cohort in turn. Check the preview before running. Save each result you want to inspect; one latest completed run is retained per operation.
  2. For Sequence alignment, Sequence ambiguity, Consensus sequence, Consensus distances, and Genetic distances, expect 5 / 3 / 4 eligible sequences. F must never appear in a sequence operation's recorded input IDs. All provided bases are unambiguous, so ambiguity counts should be zero.
  3. For Distance matrix and Tree inference, expect taxa A/B/C/D/E, A/B/C, and A/B/D/E respectively. The fixture supplies every genetic pair among those taxa. Inspect Alignment View, Phylogenetic Tree, Table fields, or the saved calculation output as appropriate.
  4. For Minimum spanning tree and Nearest neighbors, verify the scoped node IDs in the saved record. Preserve each algorithm's eligibility rules; an unsequenced or isolated node need not receive a calculated edge.
  5. For Directionality, first use 03-imported-tree.microbetrace with Full scope: its five loaded nodes match its five tree leaves. For a scoped test, use 02-configured.microbetrace, set both Tree inference and Directionality to Cohort, run Tree inference, then Directionality. A missing or mismatched tree must produce an explanation; the six-node graph includes unsequenced F, so a five-taxon inferred tree does not satisfy Full directionality's six-node population.
  6. For Threshold analysis, check Full/Visible/Cohort populations and Run. Inspect the analysis in global Settings → Filtering. Its sweep uses distance-backed inputs/range, including pairs above the current threshold; contact-only EF and imported-only AF do not affect genetic recommendations.
  7. Repeat threshold analysis after enabling nearest-neighbor pruning or lowering the current threshold. The current display mask must not discard the sweep's candidate distances. Compare recorded inputs and sweep parameters, rather than expecting the normal graph's edge count.

Expected: every successful operation records its own scope, eligible input IDs/checksum, parameters, software, timestamps, and output. Full/cohort ignore the North display subset; enabled layers still apply to graph/distance calculations. Changing one operation's scope does not change another operation's scope.

□ M15 Patristic distances and matching bootstrap taxa

  1. Load 03-imported-tree.microbetrace. Open View → Phylogenetic Tree and check five labelled tips A–E.
  2. In Investigation Workspace, set Patristic distances to Full and Run. It should complete against the imported tree. Save/reopen and verify the completed result is retained.
  3. Try Bootstrap support on this imported tree. Expect the explanation that this version supports bootstrap for sequence-derived trees only.
  4. Load 02-configured.microbetrace. Set Tree inference to Full and Run. Open Phylogenetic Tree and verify A–E. In the tree pane's Settings → Bootstrap → Calculate Bootstrap, set Replicates to 10 and disable early stopping. In Investigation Workspace set Bootstrap support to Full and Run. Inspect saved metadata and support values.
  5. Leave the five-tip inferred tree in place. Set Bootstrap support to Cohort (A/B/D/E), then try Run. Its four scoped taxa do not match the five-tip base tree.
  6. Set Tree inference to Cohort and Run to create an A/B/D/E tree. Then retry Bootstrap support in Cohort scope. Use the four-taxon cohort for a positive scoped bootstrap test; a three-tip tree may have no internal splits eligible for support.

Expected: bootstrap uses a matching taxon set and a sequence-derived base tree. A mismatched base tree produces an explanation and preserves prior completed support. The four-taxon cohort run respects hidden members D/E. Patristic calculations require an imported Newick/Auspice source, rather than an inferred-only tree.

□ M17 Cancellation and late-response protection (optional)

  1. Load 02-configured.microbetrace, set Tree inference to Full, and Run. Open Phylogenetic Tree. Set Bootstrap support to Full and complete a 10-replicate bootstrap first. Save the investigation so you have a known previous result.
  2. Set Replicates to 1000. Use the tree pane's Calculate Bootstrap, then Cancel while the progress indicator is still running. Compare the prior completed support and saved result.
  3. Start another long run. While it is running, load 02-configured.microbetrace. Wait longer than the original run usually takes. Verify that the replacement graph and its saved cohort statistics stay intact.
  4. If the tiny fixture finishes before you can cancel or replace it, record Not exercised — finished too quickly. Repeat with browser CPU throttling if available; do not count an unobserved interruption as a pass.

Expected: cancellation leaves the earlier completed output intact. Late responses cannot overwrite a newer investigation or mark a cancelled run completed. The six-node replacement must never acquire support/results from the previous five-node run.

5. Record what happened

For each case, record browser/version, current build, Pass/Fail/Not exercised, actual counts, and a short explanation. Save the session plus the corresponding record bundle for any discrepancy, and include a screenshot when layout/visibility matters. The worksheet has one row per case.

Known failures from the earlier automated run concern dashboard resize/pane lifecycle, Map centering, and an OpenFreeMap bundle assertion. They also reproduced on the base revision. Record any manual reproduction separately from an investigation snapshot mismatch.
